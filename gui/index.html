Painel de monitoramento

Uma aba por modelo. DevOps = o serviço. MLOps = o modelo. O contrato OpenAPI fica no fim da aba.

Tokens

O tokenizer conta peças (tokens), não palavras. “chegou” pode virar mais de um token.

DevOps

O processo: latência e falha do serviço.

MLOps

A mistura do texto: fatias curto / médio / longo de n_tokens.

OpenAPI — Tokens

POST /tokens

Corpo JSON. Campo obrigatório: texto (string). BentoML: mesmo contrato em /.

{ "texto": "O pedido chegou atrasado." }

Resposta 200: pedido (linha do log, com n_tokens) e relatorio.

Regressão

Número que o modelo vê. A reta devolve ŷ = a·x + b. Esse ŷ entra no KS e no PSI mesmo sem rótulo.

O valor real medido no mundo para esse x (o preço que de fato ocorreu). Sem esse campo o pedido ainda prevê ŷ, mas o MAE (erro do modelo) ignora a linha. A taxa de falha em DevOps conta crash do serviço; o MAE conta |y observado − ŷ|.

DevOps

O processo: latência e falha de software. A taxa de falha não é o erro da reta.

MLOps

A reta: ŷ, misturas baixo/médio/alto, e MAE só onde existe y observado.

OpenAPI — Regressão

POST /regressao

Corpo JSON. Obrigatório: x (number). Opcional: y_obs (number, o rótulo). BentoML: /.

{ "x": 30, "y_obs": 90 }

Resposta 200: pedido.y_hat sempre; pedido.y_obs e pedido.residual só se você mandou o rótulo (senão null); relatorio.mae usa só linhas com rótulo.

Imagens

0 é um cinza quase preto; 1 é quase branco. O classificador devolve escuro / medio / claro.

DevOps

O processo: latência e falha de software.

MLOps

Entrada (brilho), saída (rótulo), confiança.

OpenAPI — Imagens

POST /imagens

Corpo JSON. Campo obrigatório: brilho (number em [0, 1]). BentoML: /.

{ "brilho": 0.2 }

Resposta 200: pedido (rótulo, confiança) e relatorio.
